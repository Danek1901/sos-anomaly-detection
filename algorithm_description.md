# Описание алгоритма поиска аномальных респондентов

## Цель

Нужно найти респондентов, которые в конкретный день создают аномально высокий вклад в OTS отдельного бренда внутри категории. Такие респонденты могут искажать отчетную выборку, поэтому они удаляются из анализа целиком за соответствующий день.

## Единицы анализа

Аномалия ищется на уровне:

```text
SubjectID + researchdate + BrandID + CategoryDelivery
```

Итоговая единица удаления:

```text
SubjectID + researchdate
```

Если респондент признан аномальным хотя бы по одному бренду в один день, в итоговый файл `anomalies.csv` попадает только пара `SubjectID + researchdate`.

## Подготовка данных

В анализ берутся строки, удовлетворяющие условиям:

```text
BrandinDelivery = 1
CategoryDelivery не пустая
```

Если в исходных данных категория называется `CategoryNameDelivery`, код приводит её к рабочему виду.

## Расчет daily_ots

Для каждой группы считается количество строк исходного датасета:

```text
count_rows = число запросов респондента по бренду и категории за день
daily_ots = Weight * count_rows
```

## Score и порог

Для каждой категории отдельно строится распределение `daily_ots`. Чтобы снизить влияние тяжелого хвоста, используется:

```text
log_ots = log1p(daily_ots)
threshold_log = max(Q99.9, Q3 + 2 * IQR)
threshold = exp(threshold_log) - 1
score = daily_ots / threshold
```

Аномалия фиксируется, если:

```text
score > 1
count_rows >= 2
```

## Интерпретируемость

Для каждой аномалии сохраняются `SubjectID`, дата, бренд, категория, `daily_ots`, `score`, `threshold` и текстовая причина срабатывания.

Решение детерминированное и не использует вручную заданные ID, даты, бренды или фиксированный процент удалений.
